# Castle Siege · M6.3 六职业首轮平衡记录

本文件记录 M6.3 实现完成后的首轮平衡模拟。数值沿用 [M6.3_six_role_design.md](M6.3_six_role_design.md) 的首轮值，**本轮没有修改任何数值**，理由见第 5 节。

所有对局都是脚本驱动的 AI 对 AI。脚本放在临时目录，没有提交，需要时可以加进仓库。**没有真人试玩数据。**

## 1. 方法

- **对局引擎：** 使用真实的 `Battle` 和 `AIController`。双方各自用 `choose_layout()` 布防，与 `tests/test_ai.py` 的整局测试相同。
- **难度：** 双方都是 Normal（瞄准误差 ±3° / ±4，从前 3 个目标中随机选）。
- **种子与先手：** 每个种子各打一局左先手、一局右先手，所以 n=20 就是 10 个种子 × 2 种先手。
- **固定阵容：** 10 组 1v1 和 6 组 3v3，各 20 局。
- **混合阵容：** 由 AI 从六职业中随机选队，1v1 和 3v3 各 40 局。
- **补充对比：**
  - 涉及医师的 7 组对局，用同一批种子各打 40 局，比较自疗 24 和 20。
  - 3v3 中 KAE/KAB/KAG/KAM 对 KAE 各 40 局，同样用同一批种子。
- **"平局"的含义：** 30 回合到时，或双方同时全灭。
- **记录项：** 回合数、淘汰率、平局率、先手胜率；每种职业的攻击/特技/防御比例、每次行动造成的角色伤害和掩体伤害、治疗量；以及 AI 决策耗时。
- **职业缩写：** K = Knight，A = Archer，E = Engineer，G = Gunner，B = Bombardier，M = Medic。

## 4. AI 决策耗时

这组数据由单独的基准脚本测得：5 个进程并行，每档难度 6 局（3 个种子 × 互换先手），对 `choose()` 计时。

"原版代码"指从 git HEAD 导出的 `ai.py`、`battle.py`、`castle.py`、`characters.py`。

| 阵容 | 代码 | Easy：平均 / 95% / 最慢 | Normal：平均 / 95% / 最慢 | Hard：平均 / 95% / 最慢 |
|---|---|---|---|---|
| KAE v KAE | 原版 | 338 / 534 / 648 ms | 312 / 554 / 637 ms | 280 / 508 / 603 ms |
| KAE v KAE | M6.3 | 350 / 547 / 703 ms | 322 / 569 / 735 ms | 277 / 496 / 620 ms |
| GBM v KAE | M6.3 | 409 / 748 / 1190 ms | 378 / 833 / 1025 ms | 231 / 491 / 805 ms |
| KAG v KAB | M6.3 | 362 / 673 / 1049 ms | 380 / 813 / 1083 ms | 379 / 734 / 884 ms |
| 1v1 G v B | M6.3 | 280 / 496 / 591 ms | 334 / 553 / 589 ms | 323 / 529 / 576 ms |

- **旧三职业不变：** 两份代码在旧三职业对局里走出完全相同的回合数（Easy 323、Normal 342、Hard 177）。`tests/test_six_roles.py` 也用逐步回放核对过三场旧三职业对局。
- **限制额外候选：** 有散布特技可用时，AI 原本在误差范围内每隔 2 点火力取一个样本（Normal 取 5 个）。实现中改为只取 −误差、0、+误差三点，最慢一次从 1.4–1.8 秒降到 1.0–1.2 秒，第 95 百分位从约 1.1 秒降到约 0.8 秒。
- **超出的部分：** 散布阵容在最坏情况下仍比原版慢约 0.4–0.5 秒。这段时间发生在 AI 回合 2/3 秒停顿的末尾，画面上显示 THINKING。
- 第 2 节表格中的耗时是 16 个进程同时跑模拟时测的，偏高，不作为延迟结论。

## 5. 结论与是否调数值

1. **医师没有让 1v1 拖到 30 回合。** 40 局医师镜像只有 1 局平局，骑士镜像 20 局为 0 局。1v1 医师反而偏弱：对骑士、弓手、工程师都只赢 15–25%。把自疗降到 20 只是让医师镜像平均短 2.7 回合，同时让医师更弱。所以**自疗保留 24**。
2. **医师让 3v3 明显更容易平局。** KAM 对 KAE 平局 48%，对照组只有 22%，而且医师队很少输（15%）、常常打不完。降低自疗、把队友治疗改为 24、把冷却改为 5，在 40 局里都没有明显改善（48%、45%、42%，彼此在误差范围内）。所以设计文档给出的调节方向不能解决这个问题，本轮**不改数值**。下一步可以考虑的方向（未实现）：只在队友血量低于一半时允许治疗，或治疗量随回合递减。这些都改变规则，需要你来决定。
3. **三人队没有总选分裂弹。** 3v3 里 Airburst 只占投弹手回合的 5%。混合 3v3 里含投弹手的一方胜率最低（32%）。Airburst 的命中率很高（单目标 91%），但每次伤害小（6.9）。
4. **单个目标仍值得用 Power Shot。** 只剩一个敌人时，Power Shot 平均每次 13.3 HP，高于 Triple Volley 的 8.5 和 Airburst 的 6.9。Archer 的高爆发定位保持。
5. **炮手偏强、齐射偏弱。** 炮手的普通攻击与 Engineer 相当（17.4 对 18.1）；Triple Volley 每次 15.1，低于炮手自己的攻击。KAG 对 KAE 赢 58%、输 35%。炮手的强主要来自属性，不来自特技。
6. **先手优势与原三职业相近。** 1v1 骑士镜像先手胜 70%，这是原有规则的特点，不是新职业带来的。

**最终数值：与设计文档首轮值完全相同，0 项修改。**

## 6. 局限

- 只有 AI 对 AI，难度只测了 Normal。真人会更主动地用散布特技做试探，或去够墙后的目标。
- 每组 20 或 40 局只能发现明显的异常：20 局中 35% 对 25% 这样的差距不足以下结论。
- AI 用"自身误差内的平均值"评价散布特技，但仍然只在少数候选瞄准中比较，可能低估了 Airburst 越墙的价值。
