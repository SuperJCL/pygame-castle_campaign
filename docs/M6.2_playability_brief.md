# Castle Siege · M6.2 可玩性优化与 Claude Code 实施交接

目标是让玩家能主动做三个决定：先拆掩体还是尝试越过它，瞄准后是否值得现在开火，以及花掉一个回合防守能换来什么。每次出手后，玩家应能读懂结果，并用它调整下一次出手。

本文件是实施规格。先做第 1 项，再分批实施其余条目。第 1–5 项侧重交互与可玩性，第 6–8 项侧重画面。现有视觉改动仍在工作区，先检查 `git status`，保留它们和用户的未跟踪文件。使用现有 Pygame 和模块结构。规则、AI、角色数值、Reflex 周期与角度范围、本地双人掩体保密、30 回合判平及角色淘汰胜利均按当前版本执行。提交与推送按用户给 Claude Code 的授权执行。

## 当前核查

- 选队页默认选择 **Classic**。要玩摆动瞄准，依次点击 **Aim → Reflex → PLACE COVER → Confirm**（本地双人双方各确认一次），然后在己方可操作回合观察炮口。上一轮界面预览使用了 Classic。
- 用真实 Pygame 事件路径驱动当前版本，在 PvAI 左队首回合，帧 0、30、60、90 的角度依次为 **20°、34°、61°、75°**。Space 按在 75° 时，跑动开始后仍锁在 75°。这是一次脚本复现，尚未验证用户机器上具体运行的是哪个版本。
- `Game.aim_swings()` 复用 `controls_locked()`。跑动、飞行、AI 回合、结算时暂停。双人模式每方各有一份摆动进度。当前提示点半径 46 px，模式选择、角度和锁定结果分散在不同位置。这解释了为什么静态图和非瞄准阶段很难看出模式行为。

## 1. Reflex 入口、摆动与锁定反馈

**参考。** Xbox 的现场提示指南建议结合文字与视觉符号，并让关键信息在背景上可读。用于这里的判断是：玩家需要看到选中的模式、移动中的指针和已经锁定的位置。 [Xbox 视觉与音频提示](https://learn.microsoft.com/en-za/gaming/accessibility/xbox-accessibility-guidelines/103) · [Xbox 对比度指南](https://learn.microsoft.com/en-my/gaming/accessibility/xbox-accessibility-guidelines/102)

**规格。** 在选队页把现有 Aim 控件标成 `Aim style`，持续显示当前模式的一句说明。Reflex 的例句是 `The cannon swings. Press Space to lock and fire.`。布防页角落显示所选模式。战斗底栏靠近角度数值的位置提供短状态 `REFLEX · SWINGING` / `REFLEX · LOCKED 47°`，内容用实际数值。抬高当前炮口弧线的可辨识度，画出两端短刻度、实时指针和深色描边。锁定后保留锁定标记与角度直到发射完成，归属用 `PendingShot.side`，避免旧射手回程时把标记画到新一方。AI 回合用既有 `THINKING`，Classic 不画摆动弧。保留 Classic 默认、现有按钮键位和 180 帧周期。

**开发落点。** `main.py` 的 `draw_selection`、`draw_cover_screen`、`draw_swing_marks`、`draw_panel`，必要的画线辅助留在 `drawing.py`。读 `AimSwing`、`controls_locked()` 和 `PendingShot`。射击锁角继续走原有路径。

**验收。** 从选队鼠标点 Reflex 到 PvAI 开场，无需翻说明文档即可观察到完整一摆。分别用 SPACE、ATTACK、Power Shot 比对按下前显示角度、锁定提示和实际发射角度。双人检查两侧各自摆动，PvAI 检查 AI 炮口不会自行摆动；重赛仍保留模式并从原定起始角开始。

## 2. Classic 局部弹道辅助

**参考。** Team17 把训练任务与正式战役并列，帮助玩家先学会操控；早期《Worms》手册也把估算轨迹与落点视为炮术的一部分。Castle Siege 可以把少量教学直接放进瞄准过程，同时把远端落点留给玩家判断。 [Team17《Worms W.M.D Mobilize》](https://www.team17.com/news/worms-w-md-mobilize-out-now-on-apple-android) · [《Worms》原版手册](https://evercade.info/wp-content/uploads/2020/11/Worms_MD_EU_Manual.pdf)

**规格。** 人类的 Classic 可操作回合，默认在当前炮口方向显示最多六个淡色弹道点，按 `V` 隐藏或显示。每隔四个现有物理步取一个点，最多模拟 24 步，遇到首次碰撞即截断。用它替代当前长直线的主要瞄准提示，保留短炮口方向线和火力滑条。瞄准改变时即时重画；切到 Reflex、发射、AI 操作或结果页时隐藏。远端落点、伤害数值及必杀结果不显示，保留越过掩体的判断题。

**开发落点。** 若需要，在 `battle.py` 增加一个小型只读方法。创建临时 `Projectile`，调用真实 `step()` 和既有碰撞查询，绝不走 `perform_action()`。UI 只画取样点。继续让 `path_contacts()` 服务 AI，避免把它变成第二套规则。

**验收。** 左右镜像、极端角度及火力、被近处目标拦截都正确。对一组角度/火力用真实发射比较离散轨迹点。调用预览前后，炮台参数、血量、布局、回合、冷却及事件队列一致。Classic 和 Reflex 的滑条及快捷键仍可用。

## 3. 按钮显示真实技能和回合成本

**参考。** 《Into the Breach》用行动发生前的信息帮助玩家计划；Xbox 的 UI 上下文指南强调按钮应让玩家预先知道会发生什么。这里预告的是当前行动和它的用途。 [Subset Games《Into the Breach》](https://subsetgames.com/itb.html) · [Xbox UI 上下文指南](https://learn.microsoft.com/en-us/xbox/gaming/accessibility/xbox-accessibility-guidelines/114)

**规格。** 保留 Attack / Defend / Special 的三个位置。Special 的按钮文字随演员显示 `RALLY`、`POWER SHOT` 或 `REPAIR`。按键区域下方只显示一条当前操作解释，可从悬停的按钮切换，且默认提供所选角色的技能解释。示例：

| 操作 | 玩家要读到的关键信息 |
|---|---|
| Attack | 使用当前角度和火力，消耗本回合。 |
| Defend | 本回合防护；若有 Guarded Strike，解释它何时可用。 |
| Rally / Repair | 立刻结算，消耗本回合。Repair 只修尚存掩体。 |
| Power Shot | 使用当前炮位，Reflex 下先锁角。 |
| 冷却 / 无法维修 | 显示剩余回合或不可用原因。 |

**开发落点。** `Game.refresh_buttons()`、`Game.action_hint_lines()` 和 `draw_panel()`。按钮可用性继续以 `why_not_allowed()` 为准，避免为 UI 再写一套技能条件。现有日志保留详细数据。

**验收。** Knight、Archer、Engineer 切换时，按钮文字、冷却和实际行动一致；不可用按钮说明原因且点击无效。用 1280×720 检查长文字、AI 回合和 Reflex 锁角提示，保留现有面板边界测试。

## 4. 让布防成为可比较的选择

**参考。** Xbox 的 UI 上下文指南要求玩家能判断当前步骤和下一步变化。现有六块默认配置适合快速开局，但玩家很容易直接跳过八格掩体的战术价值。 [Xbox UI 上下文指南](https://learn.microsoft.com/en-us/xbox/gaming/accessibility/xbox-accessibility-guidelines/114)

**规格。** 在现有布防页提供两个可修改的六块预设，使用当前列定义。保留现有 `Inner Wall` `(0,1,2,3,4,5)`，加上 `Outer Wall` `(0,1,2,3,6,7)`，按钮下说明“高墙靠近角色 / 高墙靠近炮台”。它们是不同拦截位置，强弱取决于实际来弹角度。显示 `1/2 · Left cover`、`2/2 · Right cover`（本地 PvP）；PvAI 显示单步。按钮明确写 `Next: Right Cover` 或 `Start Battle`。悬停下层支撑块时，用同种轮廓同时标出会被移除的上层块，配一句说明。

**开发落点。** 继续使用 `CoverSetup`、`layout_problem()` 和 `remove_block()`。预设先通过既有验证，再写入当前侧。悬停可用 `remove_block()` 的返回值推算受影响格子，悬停本身只读。

**验收。** 两种预设都合法、镜像且用量相同；能编辑到零块，Back 后保留布局；本地双人看不到对手布局；AI 自动布阵不变，重赛保留双方布局。已用当前引擎的 `path_contacts()` 验证一组用例：双方各一名 Knight，左炮角度 30°、火力 88，右侧 Inner Wall 首碰掩体，右侧 Outer Wall 首碰 Knight。用正式开火路径复测这一组，作为可复现的设计例子。这个例子只证明预设能改变实际战况。

## 5. 将落点变成下一炮的反馈

**参考。** 《Into the Breach》强调让玩家看懂战术后果；Xbox 的多渠道提示指南建议用文字、图形和声音传递同一个重要事件。这里应优先解释“落在哪里、打到了谁、为什么没伤到人”。 [Subset Games 开发复盘（GDC）](https://media.gdcvault.com/gdc2019/presentations/Into%20the%20Breach%20Postmortem%20Final.pdf) · [Xbox 视觉与音频提示](https://learn.microsoft.com/en-za/gaming/accessibility/xbox-accessibility-guidelines/103)

**规格。** 顶部短消息保留最近一次出手的结论直到下一动作开始，日志继续提供明细。区分 `DIRECT HIT`、`COVER HIT`、`GROUND IMPACT` 和 `OUT OF FIELD`，并根据真实事件补充一条结果。例如 `COVER HIT · Archer shielded` 或 `GROUND IMPACT · Archer −18 HP`。有多人受伤时优先概括人数，详细姓名放日志。在真实落点画短暂收缩的描边及两三颗碎片线条，与现有爆炸和飘字共用寿命；出界只给文字。结算页优先显示胜负原因。

**开发落点。** `Game.show_event()`、`describe_event()`、`draw_battlefield()`。从现有事件的 `kind`、`target`、`covered`、`characters_hit` 与 `blocks_hit` 生成反馈；直接命中和地面溅射按 `kind` 区分。同一炮的事件由现有更新循环消费一次。仅用 Pygame 图形和现有声音，保留人物、血条和准星的优先可见性。

**验收。** 脚本复现直击、掩体拦截、地面溅射、地面空爆、出界、同一炮击毁掩体但角色仍被遮护、击败后进入结算。关闭声音后仍能区分结果；换队和重开清空旧反馈。确认画面上的位置和数值与引擎结果相同。

## 6. 小组片头与角色阵容页

**画面目标。** 启动时先记住小组和游戏名称。进入选队后，第一眼能认出三种职业。用现有山谷背景、深蓝底、暖金标题和两队几何队徽形成统一的片头与选队画面。

**开场署名。** 小组「66大顺组」的英文片头用 **Double Six Studio**。Double Six 保留「66」的双六意象，配两枚各有六个点的暖金方印。片头字标使用 `DOUBLE SIX STUDIO`，小组署名和游戏标题分开出现。图标用 Pygame 圆点与圆角方框直接画，英文组名放在一个常量中。

**开场动画。** 程序启动时显示深蓝底，两枚六点方印和 `DOUBLE SIX STUDIO` 淡入，短暂停留，再淡出接到现有选队页的 `CASTLE SIEGE`。总时长约 1.2 秒。允许鼠标点击、Space、Enter 跳过，Esc 仍退出。片头期间普通点击只负责跳过，不穿透到下方角色或启动按钮；后续正常输入交回原选队处理。每次启动只播一次，Rematch、Change teams 和布防返回均不重播。用 Pygame 的时钟和透明度绘制，不用阻塞等待、视频或新游戏状态。

**角色图。** 保持左右各三张阵容卡的位置，把现有小图改为更大的半身像，优先展示轮廓、职业名和一行核心数值。Knight 用宽肩甲和盾牌，Archer 用尖兜帽和斜持弓，Engineer 用低檐安全帽和短柄锤。选中后显示队徽与站位，角色支持左右两队复用，颜色由外框或队徽表达。技能文字优先保留技能名与一句实际效果。中央区域只保留开始布防的主按钮。

**素材规格。** 可做一张透明 PNG 角色图集，三格各 160×192 px，统一镜头、光向、线宽和透明边距。选队卡内显示约 90×100 px，启动时裁切、缩放并缓存。可交给画师或图像生成工具的简报：*原创手绘中世纪策略游戏半身像；海军蓝阴影、暖金边光；同一比例的骑士、弓手、工兵；武器形状清晰；透明底；无文字、无队徽、无边框。* 缺少图片时用现有 Pygame 角色绘制回退。3D 模型、视频及逐帧角色贴图不在这批范围。 [Team17《Worms W.M.D》官方预告](https://www.youtube.com/watch?v=BlPidIlVvGQ)

**验收。** 截片头、三角色未选中和已选中画面。验证片头自然结束、三种输入跳过、无误选、重赛不重播。全屏和窗口内均能快速认出三职业；未选、已选和 AI 方不可选状态有文字或形状区别。

## 7. 重做战场的前后景与单位轮廓

**画面目标。** 现有山谷插画继续做远景，画面最抢眼的元素应是炮弹、可操作单位和掩体。让前景像同一个世界，避免插画背景和纯色地面看起来像两张图拼在一起。

**构图。** 远景保留冷蓝山谷和暖色天光；对角色与掩体所在高度使用低饱和暗底，弱化角色身后的树影细节。用现有地面边界画出窄石土层、间断草边和短接触影，明确哪里才是可碰撞的地面。前景元素统一用深描边和少量亮边分层。左、右用保留的圆形／菱形区分；木、金属、石材分别靠轮廓与少量纹理识别。掩体完整、受损、摧毁三个状态在灰度下也有形状差异。可以重画炮架与战场角色的笔触，保留角色跑动和当前物理位置。

**实现材料。** `drawing.py` 的 `make_background()` 缓存地面和环境层，`draw_block()`、`draw_figure()` 与 `main.py` 的 `draw_cannon()` 用同一组描边和材质色。沿用现有背景文件、角色脚底坐标、炮口及命中框。暗底和绘制阴影只是表现层；背景不加入看起来像可破坏掩体的近景物件。可参考《Worms W.M.D》用手绘环境与可操作物体组织画面，实际素材沿用自己的山谷风格。 [Team17《Worms W.M.D》](https://store.steampowered.com/app/327030/Worms_WMD/) · [Xbox 对比度指南](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/102)

**验收。** 固定同一场景做 1280×720 前后对照，再缩到 640×360 和转灰度。检查左右炮台、存活角色、被选角色、受损掩体和弹道都可辨；对照原炮口及地面位置。用 3v3、两边满掩体及炮弹飞行同时在场的画面复查。

## 8. 统一战斗面板与结算的视觉层级

**画面目标。** 平时先看到“谁的回合、谁在行动、角度和火力”，其余细节跟随视线往下。结算时同一视线位置读到赢家和胜负原因。

**布局规格。** 在现有 1280×720 和底栏起点 y=580 内重排。顶部中央用带队徽的实底回合条，左右只放各队存活数/总人数，次要信息用小一档字号。底栏按左侧角色、中央操作、右侧战报分组，间距比边框更显眼。中央用最大字号显示角度和火力；当前可用主操作用暖金，其他操作保留同一高度和可读文字；不可用、冷却、锁定用字样加形状区别。右侧最新落点消息提高对比度，较早的日志次之。结算沿用战场作背景，中央实底结果面板按队徽与赢家、胜负原因、回合数和下一步按钮排序；Draw 使用独立的文字和中性徽记。

**实现材料。** `draw_hud()`、`draw_panel()`、`draw_result()` 和 `drawing.Button.draw()`。动作信息接第 3 项，命中内容接第 5 项。颜色沿用深蓝底、暖金操作色及左右队徽色；标准信息文本对背景以 4.5:1 为设计目标。选队主按钮与结算 Rematch 沿用同一套按钮样式。字体先用项目已有 Pygame 字体，靠大小、字重和留白建立层级。 [Xbox 文字显示指南](https://learn.microsoft.com/en-us/gaming/accessibility/xbox-accessibility-guidelines/101) · [Xbox 对比度指南](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/102)

**验收。** 对照 Classic、Reflex、AI 回合、长技能名和满员战场，测底栏文字与按钮不重叠，滑条响应区和绘制位置一致。结算分别截图左胜、右胜、30 回合平局。请试玩者只看画面指出当前队伍、火力位置和下一步按钮，记录需要提示的地方。

## 真人验收补改：本地双人左右键位

试玩反馈：两个玩家共用方向键，需要轮流挪手。右炮朝左，按右键提高火力也与画面方向相反。本地双人使用左右两组按键，水平键统一遵循「朝场地中央加力，朝己方边界减力」。

| 本地双人 | 抬高 / 压低炮口 | 增大 / 减小火力 | 普通攻击 |
|---|---|---|---|
| 左队 | W / S | D / A | F |
| 右队 | ↑ / ↓ | ← / → | Enter |

- 左右只在各自的可操作回合响应己方键位。PvAI 保留方向键与 Space。角色选择、鼠标按钮和火力滑条沿用现有操作。上下键只在 Classic 手动调角；Reflex 用本侧开火键锁角，Power Shot 继续走现有锁角路径。
- 键位只作用于战斗。进入战斗前 Enter 仍确认布防，片头仍可用 Enter 跳过。按住 F 或 Enter 跨过回合或从布防进入战斗，必须松开重按才会开火。两侧都沿用 Shift 快调、火力边界和现有输入锁；长按瞄准键可重复调节。
- 在回合操作区按实际玩家与模式显示键位，例如右队显示 `POWER · ←+ / →−`、`ATTACK · Enter`，左队显示 `POWER · D+ / A−`、`ATTACK · F`。同步 README。实现集中在 `main.py` 的战斗键位处理和对应提示，避免把左右键位写进炮台或战斗规则。
- 验收：在同一台键盘上各用本侧键位调炮、发射，交换回合后按对方键位不会改当前炮；同火力左右弹道仍镜像。右队试一次 Classic 加力和 Reflex 锁角，另测长按开火键、Enter 确认布防、右侧先手重赛及 PvAI 原键位。此次只补改本地双人键位，提交仍等用户复验。
