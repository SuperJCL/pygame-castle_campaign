# Castle Siege — M4.3 final gameplay stabilization report

Baseline: `3fae982` (M4.2-B.1). Gameplay is feature-frozen: M4.3 added no mechanics, AI features,
characters or modes. All checks below ran on the real game code; the scripts that drive them
are throwaway and not part of the project. Screenshots are in `docs/screenshots/`.

## 1. Summary

- **No gameplay defect was found.** No code was changed in M4.3; only this report, the
  screenshots and the documentation status lines were added.
- **Automated tests:** 405 tests, all passing with Pygame (section 3).
- **End-to-end:** 72 complete matches played through the real interface (36 setups) with no
  exception, no refused action, no stuck state, and a clean Rematch and Change teams in every one.
- **Critical interactions:** all 11 scripted checks passed (section 5).
- **Pacing and difficulty:** 200 seeded matches. Easy < Normal < Hard holds; 3v3 matches usually
  finish before round 30; no invalid action (section 6).

## 4. Seeded end-to-end matrix

36 setups: PvAI Easy, Normal and Hard, and PvP; × 1v1, 2v2, 3v3; × default, empty, custom
cover. Each setup played a LEFT-first match, a Rematch (RIGHT first), then Change teams.
The human side is an AIController deciding the move, which then clicks the character, aims with
the arrow keys and clicks the button.

| | 1v1 | 2v2 | 3v3 |
|---|---|---|---|
| Rounds to the end (all 72 matches) | 3–21 | 4–25 | 5–30 |
| Ends by elimination | 24 / 24 | 24 / 24 | 23 / 24 (one Easy timeout draw) |

Every result screen matched the Battle's winner and reason and played one tune (victory 39,
defeat 32, draw 1). After every Rematch: round 1, first mover swapped, all sounds stopped, no
runner, shot, floater or trail left, no Guarded Strike, Defend allowed again. After every
Change teams: back to selection with the picks kept.

## 6. Pacing and difficulty (200 seeded matches, current rules)

3v3, each AI with its own team and cover.

| Mirror | Finished before round 30 | Average rounds |
|---|---|---|
| Easy v Easy (40) | 37 (92 %) | 22.9 |
| Normal v Normal (40) | 38 (95 %) | 21.4 |
| Hard v Hard (40) | 40 (100 %) | 13.1 |

| Head-to-head (40 each, sides and first movers swapped) | Result |
|---|---|
| Easy v Normal | Normal 28, Easy 9, draws 3 |
| Normal v Hard | Hard 37, Normal 3 |

No invalid action in any of the 200 matches. Guarded Strike and the anti-stall rule were measured
in M4.2-B with the same code (`docs/M0_design.md`, "M4.2-B notes"): never defending still wins
most (60 %), so repeated Defend is not dominant, and a player who defends whenever allowed must
strike every other turn. These numbers describe the built-in AI, not skilled human play.

## 8. Issues found and fixes

- **Gameplay defects:** none found; no fix was needed.
- **Found in my own check scripts** (not in the game): a wait loop that never ended once the
  shot had landed, and an older screenshot script that tried to pass every turn with Defend,
  which the anti-stall rule correctly refuses. Both scripts were fixed; the game was not
  changed.

**Gaps that could affect grading:**
- **Report completeness (M5):** the final report, a class diagram, the demo video and the report's
  screenshots are not done yet. The screenshots in `docs/screenshots/` can be reused.
- **Sample formulas:** damage is deterministic (ATK − DEF, minimum 1), not the instructor's
  sample with a random −5 to +10 (§4.8). EXP numbers are our own. This is documented; we don't
  claim to match the samples.
- **Custom rules not approved by the instructor:** the round-30 draw, deployable cover, Cover Guard,
  Guarded Strike and the anti-stall rule (listed in `docs/M3.3_course_compliance.md`).
- **Clean code:** `main.py` is about 1,400 lines (one class per screen group would split it, but
  M4.3 did not reorganize modules).
- **Stale history:** some rows of `docs/M0_design.md` §9 still describe the M1 castle prototype
  (two castles, the 60 % rule) as the original plan; the current rules are in the M3.4–M4.2 blocks
  at the top of that document.

## 10. Known limitations

- **Balance and pacing describe the built-in AI**, not skilled human play; the numbers come from
  limited seeded runs (40 matches per cell, about ±8 points of noise).
- **The real-window check was not repeated in M4.3.** The end-to-end matrix drives the same
  click and key handlers, headless.
- **Button hover** can't be shown by posted messages without moving the user's cursor; a test
  fakes the mouse position.
- **The sounds** are simple synthesized effects.
